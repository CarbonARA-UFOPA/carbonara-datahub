Os dados das estações chegam a este servidor, passam pelo controle de qualidade e ficam num banco de séries temporais (PostgreSQL/TimescaleDB). O acesso é pela API de dados ({{ api_url }}, documentação interativa em {{ api_url }}/docs) com uma chave pessoal — peça a um administrador da plataforma. Cada consulta leva a chave no cabeçalho X-API-Key.

2. Séries temporais

GET {{ api_url }}/series?station=eddyfarm&vars=air_temp,rel_humidity&start=2026-08-01T00:00:00Z&end=2026-09-01T00:00:00Z
    &agg=raw|1h|1d       # raw = cada registro; 1h/1d = média, mín, máx e nº de amostras APROVADAS
    &qc=good|all         # (raw) good = só valores aprovados; all = tudo, com o flag de qualidade
    &tz=America/Santarem # fuso dos carimbos na resposta (padrão UTC)
    &format=json|csv     # csv = formato longo (time, station_id, variable_id, value, quality)
    &start=now-7d        # atalhos: now, now-12h, now-7d, now-4w
GET {{ api_url }}/latest?station=eddyfarm        # último valor de cada variável

Limites: respostas cruas param em 20 mil pontos (100 mil com chave download); agregados em 100 mil intervalos. Para períodos longos prefira agg=1h ou 1d.

3. Qualidade dos dados (quality)

FlagSignificadoComo usar
0aprovadouse
1valor não numérico no arquivo (NAN, texto)o valor vem nulo
2fora da faixa física definida para a variáveldescarte ou investigue
3salto maior que o aceitável entre duas leituras seguidasprovável ruído
4valor travado: N leituras iguais seguidas (sensor parado)descarte

Nenhum valor é alterado ou removido pelo controle de qualidade: o dado cru fica no banco com o flag. Os agregados (1h/1d) consideram só quality = 0 e informam quantos valores ficaram de fora (n_flagged).

4. Exemplos

Python (pandas)

import pandas as pd, requests
API, KEY = "{{ api_url }}", "cbk_..."
r = requests.get(f"{API}/series", headers={"X-API-Key": KEY},
                 params={"station": "eddyfarm", "vars": "air_temp,rel_humidity", "agg": "1h",
                         "start": "2026-08-01T00:00:00Z", "end": "2026-09-01T00:00:00Z", "format": "csv"})
df = pd.read_csv(pd.io.common.StringIO(r.text), parse_dates=["bucket"])
wide = df.pivot(index="bucket", columns="variable_id", values="avg")

R

library(httr); library(readr)

df <- read_csv(content(r, "text"))

Linha de comando

curl -H "X-API-Key: cbk_..." "{{ api_url }}/latest?station=eddyfarm&tz=America/Santarem"
curl -H "X-API-Key: cbk_..." "{{ api_url }}/series?station=eddyfarm&agg=1d&start=now-365d&format=csv" -o eddyfarm_diario.csv

5. Boas práticas

  • Guarde a chave como variável de ambiente, nunca em código versionado; ela pode ser revogada e trocada a qualquer momento.
  • Os carimbos estão em UTC; use tz= só para exibição. O fuso original de cada arquivo está registrado na dashboard.
  • Cite a variável pelo variable_id (estável); o rótulo humano e a unidade vêm em /variables.
  • Para bases grandes, baixe uma vez por período (format=csv) e trabalhe localmente; a API tem limite de requisições por minuto.
  • Dúvidas sobre sensores, alturas e calibrações: fale com a equipe da estação — a dashboard mostra, por arquivo, o que está sendo ingerido e com quais regras.
